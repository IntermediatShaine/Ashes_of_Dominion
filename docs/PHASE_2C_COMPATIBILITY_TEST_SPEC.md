# Phase 2C — Generation compatibility and persistence test specification (PROPOSED)

> **Current-main update (2026-11-06):** This is a historical Phase 2C proposal based on the 2026-11-01 schema-1 baseline. Merged Stage 1/2 PRs subsequently introduced schema 3 and partial POI Save/Continue. Refer to the [2026-11-06 reassessment](PHASE_2C_COMPATIBILITY_2026-11-06.md) for actionable architecture and tests. This historical proposal never constituted owner approval to implement a save policy.


**Status:** Not implemented. **Verified baseline:** main aec6ce9, SaveGame.SCHEMA_VERSION = 1 and UniverseState.CURRENT_GENERATION_VERSION = 1.

## Actual behavior and compatibility hazards

UniverseState.to_dict serializes world_seed as a string and generation_version as an integer; from_dict currently defaults a missing generation_version to CURRENT_GENERATION_VERSION. validate() rejects values outside 1..CURRENT_GENERATION_VERSION. UniverseFactory.create sets the current generation version for a new universe. GameSession._bind passes the saved version to WorldGraphGenerator.generate; ExpeditionService.build_area passes it to WildernessGenerator.generate.

Both generators accept generation_version and put it into seed-derivation labels. **Neither selects a versioned algorithm implementation.** Every load also uses today's content tables: landmarks, biome settings, world-map/wilderness balance, enemy and resource pools, and the currently available decision. Merely preserving an integer will not freeze a preexisting world if code or generation input data changes. The current generation tests check same-seed behavior against themselves; there are no locked historical v1 fixtures.

The story-anchor contract is grounded in the design: persistent settlements, important cities, story landmarks and required NPC placements stay meaningful while wilderness, routes and resource/encounter placement vary.

## Required before any algorithm/content change

1. Capture **v1 golden fixtures on the verified baseline** for chosen seeds including 0, a negative seed, and a 64-bit seed outside exactly representable JSON-number range. Include world-graph fingerprint, all persistent anchor IDs/coordinates/metadata, waypoint IDs/coordinates, complete edge topology/cost/danger; for at least two destination/biome configurations, include terrain bytes or canonical digest, resource/enemy spawn key/location/type, decision spawn location, reachable-space checks and resource regrowth samples. Commit the fixture-producing script and fixture files with provenance (engine 4.5.1, baseline SHA, content digests, fixture input params).
2. Freeze the v1 algorithms **and their effective generation input data**. Versioned content tables or an immutable v1 parameter/anchor bundle are required for faithful replay; pin the sources for graph generation and area generation. If current content is mutable for balance, separate gameplay tuning from inputs that influence saved-world topology and placements.
3. Implement explicit dispatch for **both** WorldGraphGenerator and WildernessGenerator (e.g. generate_v1 / generate_v2). New universes use CURRENT_GENERATION_VERSION = 2 only when v2 is deliberately introduced. Existing saved v1 universes continue to use v1 behavior; do not rehash or reroll old seed labels.
4. Preserve immutable story anchors independently of procedural waypoint/terrain changes; anchor IDs/positions must be checked in cross-version tests and cannot be silently moved by new region definitions. For intentional story redesign, require a separately reviewed anchor migration and saved-world compatibility contract.
5. Treat save **schema version** and **generation version** separately. SaveMigrator changes data layout when necessary, never silently upgrades the algorithm version. Unknown or future generation versions must fail with a controlled, readable error. Require explicit generation_version for every supported save layout; if older historical fixtures truly omitted it, map only those known formats to v1 in a documented schema migration. The current default-to-current behavior must not reinterpret an old world as the newest algorithm.
6. Validate that saved revealed_edge_ids and ExpeditionRecord.route_edge_ids resolve in the **historical generated graph**. World-modification resource keys and area IDs must still refer to the same generated nodes. Fail safely rather than resetting discovery, spawning unearned loot or moving critical narrative sites.
7. Run a pre-change v1 baseline and compare it with v1 generated by the new dispatcher and content bundle; byte/canonical equality for exact fixtures, plus functional reachability and story-anchor assertions. Produce a report of any intentional v2 differences without changing v1.

## Implementation-ready scenario matrix

| ID | Scenario / arrange | Expected assertion |
| --- | --- | --- |
| G01 | v1 fixture, same seed, two clean processes | Exact canonical graph and area fingerprints/records |
| G02 | v1 save loaded after v2 code exists | Same anchor positions, topology, node IDs, danger and spawn keys as historical v1 |
| G03 | Two new v2 universes with same seed and pinned input bundle | Identical topology, area placement and route estimates |
| G04 | Old v1 and new v2 with the same seed | Both satisfy common story anchors; intentional wilderness differences documented, not required to be always different |
| G05 | Loaded v1 with harvested key and in-range regrowth day | Same node remains depleted; no duplicate haul/XP; returns after regrowth |
| G06 | Loaded v1 with revealed edges and an active route record | Edges still exist; Mist visibility and destination/route records unchanged |
| G07 | Missing, zero, negative, unsupported future generation_version | Controlled rejection or narrowly documented legacy mapping; no silent fallback |
| G08 | Schema 1→2 with v1 generation_version | Algorithm stays v1; all three state scopes + 64-bit string RNG states preserved |
| G09 | Seed above 2^53, negative seed, seed 0; Windows/Linux Godot 4.5.1 | Exact textual seed/RNG state and matching canonical fixture digests |
| G10 | NPC decision previously resolved, or NPC spawn still pending | No replay of decision effects; same v1 event placement for pending state |
| G11 | Corrupt save with valid backup; orphaned temp; failed promotion | Recover last valid verified snapshot without overwriting it |
| G12 | Engine/fixture upgrade rehearsal | No changes to v1 hashes without explicit approved compatibility change |

Use deterministic, sorted serialization for fixture digests: names and coordinates, edge IDs, terrain bytes, spawn keys, type/amount and placement. The existing WorldGraph.fingerprint and WildernessMap.fingerprint are useful checks but are **not complete contracts** (e.g. graph story text/content metadata and actor runtime state need separate assertions).

## If resumable expeditions are approved: checkpoint scenarios

| ID | Scenario / arrange | Expected assertion |
| --- | --- | --- |
| S01 | Save after movement, quit process, Continue | Same world-space player position, facing, health, destination and route; no teleport to spawn |
| S02 | Partially damaged living enemy, dead enemy and patrol timer | Same stable actors, HP, death state, positions, FSM phase/timers/target and private RNG; no respawn |
| S03 | Harvest two resources, collect rewards, save/reload | Exact haul, depletion, XP and resource state; no duplicate reward or pickup |
| S04 | Resolve NPC choice, save/reload and revisit | Decision/morality/reputation applied once; NPC has no repeat choice |
| S05 | Save during safe combat boundary, continue with known RNG state | Next damage/reward draws match a no-reload control execution |
| S06 | Crash before temp verification, during rotation, or before final promotion | Old valid checkpoint/backup recovered; no mixed snapshot sections |
| S07 | Save with pending resurrection transition | Recovery applies the transition once and routes to settlement, not a resurrected combat scene |
| S08 | Schema-1 save with no checkpoint, including artificial active record | Ordinary idle save loads; legacy active record is handled explicitly, not silently replayed |
| S09 | Checkpoint has mismatched area fingerprint or unknown actor ID | Validation error and recovery path; original saves untouched |
| S10 | N consecutive save/reloads in the same active expedition | No cumulative drift in position, counters, inventory, enemy health, decisions or RNG |
| S11 | Quit/relaunch when the last save is in an active expedition | Two-process Continue enters exploration and passes a full-state comparison |
| S12 | Checkpoint size and pause/save latency on target Windows hardware | Recorded measurements meet owner-approved budgets or regressions are reported |

All testing includes script/scene imports, unit/persistence/deterministic/integration suites, headless boot and two-process relaunch. Inject failures into the actual save boundary (including primary-corrupt/backup-valid). Use deterministic scripted combat steps and explicit snapshot comparison; do not claim raw player-input feel from a headless test.

## Required vs optional future work

**Required:** v1 fixture baseline, version dispatch, immutable/versioned v1 generation inputs, explicit reject/migrate policy, cross-platform v1 regression coverage, checkpoint-specific tests only if resume is approved.

**Optional later:** visual replay playback, content-manifest automation, compression, per-chunk lazy deltas, world-state event sourcing, support for arbitrary Godot engine upgrades and migration/removal of historical generators. None is a substitute for preserving v1 while old saves are supported.

**Validation claim:** These scenarios are a specification, not tests executed during this review.
